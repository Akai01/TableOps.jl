TableOps.jl

Fast, tidyverse- and SQL-style table verbs for any Tables.jl table, in pure Julia with Tables.jl as the only dependency.

TableOps

Fast, tidyverse- and SQL-style table verbs for any Tables.jl table.

source
TableOps.Table — Type
Table(x)
Table(; name = column, ...)

A table with named columns. Table(x) accepts any Tables.jl table, and Table(; a = [1, 2], b = ["x", "y"]) builds one from keyword columns, in keyword order.

Columns are shared, not copied: Table(x) keeps the source's column vectors as they are, so changing a vector in place changes every table that holds it. A column that is not an AbstractVector is collected into one. A Table passed to Table is returned as is.

t.revenue returns the stored column, whatever the column is called, and throws an ArgumentError with a suggestion for an unknown name. A Table cannot be changed in place: t.revenue = v throws. names(t) returns the column names as a Vector{Symbol} (a copy). copy(t) copies every column with copy, so the result is independent of t except for the elements themselves: a column of vectors shares its inner vectors. isequal compares names and columns with isequal; == follows Julia's three-valued rule and can return missing.

Every column must use 1-based indexing, all names must be unique, and all columns must have the same length; otherwise an ArgumentError says how to fix it.

Examples

julia> using TableOps

julia> Table(; a = [1, 2], b = ["x", "y"])
2×2 Table
     a  b
 Int64  String
 ─────────────
     1  x
     2  y

A Table prints its size, the column names and types and the first and last rows, fitted to the display; glimpse shows one line per column. In the REPL, rows and columns are fitted to the screen; written elsewhere, all rows and columns are shown.

Column pickers

TableOps.AbstractSelector — Type
AbstractSelector

The supertype of column pickers such as everything(), of_type(T) and except(...). To add a picker, subtype it and add a method of the one public signature

resolve(selector, t::Table)::Vector{Symbol}

which returns the picked names, in order and without repeats. It may look at names(t) and at the element types of the columns of t.

Examples

julia> using TableOps

julia> import TableOps: resolve

julia> struct LastColumn <: AbstractSelector end

julia> resolve(::LastColumn, t::Table) = [last(names(t))];

julia> resolve(LastColumn(), Table(; a = [1], b = [2]))
1-element Vector{Symbol}:
 :b

julia> select(Table(; a = [1], b = [2]), LastColumn())
1×1 Table
     b
 Int64
 ─────
     2

TableOps.resolve — Function
resolve(picker, t::Table)

The names of the columns of t that picker picks, as a Vector{Symbol}. A picker is a name (Symbol or String), a vector of names, a predicate on the column name as a String (startswith("re"), endswith, contains, or any function that returns true or false), everything(), of_type(T), except(picks...) or a subtype of AbstractSelector. A name that is not a column is an error; a predicate that picks nothing gives an empty vector. A name in a vector appears once, at its first place.

Examples

julia> using TableOps

julia> t = Table(; revenue = [1], region = [2], cost = [3]);

julia> resolve(startswith("re"), t)
2-element Vector{Symbol}:
 :revenue
 :region

julia> resolve(of_type(Int), t)
3-element Vector{Symbol}:
 :revenue
 :region
 :cost

TableOps.of_type — Function
of_type(T)

A column picker for the columns whose element type is a subtype of T. missing is ignored: a Union{Missing,Float64} column is a Float64 column. A column whose element type is Missing (such as [missing, missing]) is picked only by an of_type(T) with Missing <: T. An empty column of element type Union{} is picked by every of_type. Bool is an Integer, so of_type(Integer) picks Bool columns too; use of_type(Int) to avoid it.

Examples

julia> using TableOps

julia> t = Table(; a = [1, 2], b = [1.5, missing], c = ["x", "y"]);

julia> resolve(of_type(Real), t)
2-element Vector{Symbol}:
 :a
 :b

Column verbs

TableOps.select — Function
select(t, picks...; new = :old, ...)
select(picks...; new = :old, ...)

A table with the columns that picks pick, in the order they are picked, followed by the keyword columns new = :old, each of which adds the column old again under the name new. A column picked twice appears once; a column that is both picked and renamed appears under both names. Columns are shared with t, not copied. A pick is any column picker (see resolve); an empty result or two columns with the same name is an error. The second form returns a function of a table, for use with |>.

Examples

julia> using TableOps

julia> t = Table(; a = [1, 2], b = ["x", "y"], c = [1.5, 2.5]);

julia> names(select(t, :c, :a))
2-element Vector{Symbol}:
 :c
 :a

julia> names(select(t, startswith("b"); total = :c))
2-element Vector{Symbol}:
 :b
 :total

julia> names(t |> select(:a))
1-element Vector{Symbol}:
 :a

TableOps.rename — Function
rename(t; new = :old, ...)
rename(; new = :old, ...)

A table with the column old called new, for each keyword, in the same place. Renames apply together, so rename(t; a = :b, b = :a) swaps two names. Columns are shared with t, not copied. Giving a column two new names, or two columns the same name, is an error. The second form returns a function of a table, for use with |>.

TableOps.mutate — Function
mutate(t, specs...; name = spec, ...)
mutate(specs...; name = spec, ...)

A table with the columns that the keyword specifications compute, added at the end, or replacing the column of the same name in its place. Specifications run in the order written and each sees the table with all earlier results, so mutate(t; b = :a => each(x -> x + 1), c = :b) works. The specifications are:

SpecMeaning
name = :aa copy of column a
name = :a => ff(a), a function of the whole column
name = [:a, :b] => ff(a, b)
name = :a => each(f)f applied to each element of a
name = t -> …a function of the table so far
name = valuea constant, repeated for every row
name = vectora new column, one value per row

A Symbol on the right of name = is a column, a String is a constant. A result of length 1 is repeated for every row; any other length except the row count is an error. A result that is not a Vector (a range, a view) is copied into one. A result that is a column of the table is copied, so a column that mutate makes never shares a vector with another column; a vector you pass that is not a column of the table is kept as it is, not copied, as in Table. A result with an abstract element type, such as Vector{Any}, becomes a vector of the one concrete type it holds (plus missing), or Vector{Missing} when it holds no value other than missing; a mixture of types is an error. A tuple, NamedTuple, matrix, set, dictionary, table, generator, skipmissing, keys, values or other Base.Iterators iterator is an error, not a constant: write name = [x] to put one in every row. nothing is an error too; use missing for an absent value. Unchanged columns are shared with t. A specification without a name, such as mutate(t, :a => sum), is an error. A table with no columns has no rows. The second form returns a function of a table, for use with |>.

Examples

julia> using TableOps

julia> t = Table(; a = [1, 2], b = ["x", "y"], c = [1.5, 2.5]);

julia> pull(mutate(t; d = :a => each(x -> x + 1)), :d)
2-element Vector{Int64}:
 2
 3

julia> pull(mutate(t; total = [:a, :c] => (a, c) -> a .+ c), :total)
2-element Vector{Float64}:
 2.5
 4.5

julia> pull(mutate(t; region = "EU"), :region)
2-element Vector{String}:
 "EU"
 "EU"

Row verbs

TableOps.where — Function
where(t, conditions...)
where(conditions...)

Keep the rows of t for which every condition is true. A condition is a Bool column name such as :flag, :col => f, [:a, :b] => f, :col => each(f), or a function of the table such as t -> t.x .> 1.

true keeps a row; false and missing drop it, as SQL WHERE does. So !(x == 1) also drops the rows where x is missing. Conditions are combined with AND, and each one sees the whole table. A single value, or a vector of length 1, applies to every row; any other length is an error, and so is a value that is not Bool or missing. With no conditions the table is returned as it is.

The result never shares columns with the input. Conditions are positional; to add a column use mutate. The form where (x), with a space, does not parse.

Examples

julia> using TableOps

julia> t = Table(; a = [3, 1, 2], b = ["x", "y", "z"]);

julia> pull(where(t, :a => each(>(1))), :b)
2-element Vector{String}:
 "x"
 "z"

julia> pull(t |> where(tt -> tt.a .< 3), :b)
2-element Vector{String}:
 "y"
 "z"

TableOps.arrange — Function
arrange(t, keys...; by_group = false)
arrange(keys...; by_group = false)

Sort the rows of t by one or more keys. A key is a column name (:a or "a") for ascending order, or desc(:a) for descending order. The sort is stable: rows that tie keep their input order, and later keys break ties of earlier ones.

missing comes last in both directions. NaN comes after Inf in ascending order and first in descending order. -0.0 and 0.0 are the same key, so they tie. Strings sort by Unicode code point, not by locale, and false comes before true. Each key column needs one element type, apart from missing, that isless can compare, such as numbers, strings, symbols or dates.

by_group = true is for grouped tables and is an error on a plain Table. The result never shares columns with the input.

Examples

julia> using TableOps

julia> t = Table(; a = [3, 1, 2], b = ["x", "y", "z"]);

julia> pull(arrange(t, desc(:a)), :b)
3-element Vector{String}:
 "x"
 "z"
 "y"

julia> pull(t |> arrange(:a), :b)
3-element Vector{String}:
 "y"
 "z"
 "x"

TableOps.distinct — Function
distinct(t, picks...; keep_all = false)
distinct(picks...; keep_all = false)

Keep the first row of each distinct key, in the original order. The key is the columns that picks pick (any column picker, see resolve); with no picks it is every column. The result has the picked columns in pick order; with keep_all = true it has every column of t, taken from the first row of each key.

Keys are equal when they are isequal (so missing is one value and NaN equals NaN), with one addition: -0.0 equals 0.0, and the value of the first row is kept. A pick that picks no column is an error, because a table without columns has no rows. The result never shares columns with the input.

Examples

julia> using TableOps

julia> d = Table(; a = [1, 2, 1], b = ["x", "y", "x"]);

julia> pull(distinct(d, :a), :a)
2-element Vector{Int64}:
 1
 2

julia> nrow(d |> distinct())
2

TableOps.slice — Function
slice(t, rows)
slice(rows)

Keep the rows of t with the given row numbers. rows is one integer, a range or a vector of integers (any integer type, but not Bool). The rows come in the order given and duplicates are kept, so slice(t, [3, 1, 1]) returns row 3, then row 1 twice. A number outside 1:nrow(t) (zero, negative or too large) is an error that shows the first bad number and the valid range. There are no negative numbers to drop rows, and a Bool vector is an error: to keep rows by a condition use where.

In the pipe form the row numbers are checked when slice(rows) is called and their range when the result is applied to a table. The result never shares columns with the input.

Examples

julia> using TableOps

julia> t = Table(; a = [3, 1, 2], b = ["x", "y", "z"]);

julia> pull(slice(t, [3, 1]), :b)
2-element Vector{String}:
 "z"
 "x"

julia> pull(t |> slice(2:3), :b)
2-element Vector{String}:
 "y"
 "z"

TableOps.slice_min — Function
slice_min(t, col; n = 1, with_ties = true)
slice_min(col; n = 1, with_ties = true)

Keep the n rows of t with the smallest values of the column col, in ranked order, smallest first. Rows with equal values keep their input order. The ranking is the order of arrange: NaN is the largest value, and -0.0 and 0.0 are the same value.

With with_ties = true (the default) every row tied with the n-th value is kept, so the result can have more than n rows; with with_ties = false it has exactly n. n is a whole number of 0 or more (any integer type, but not Bool) and defaults to 1; when the column has no missing, an n larger than the number of rows returns all rows. n = 0 gives no rows and keeps the column types.

missing is last in the ranking and is never selected. If the column has missing values and n is larger than the number of other values, that is an error that shows both numbers; drop the missing rows first with where, or lower n. The column needs one element type, apart from missing, that isless can compare. The result never shares columns with the input.

Examples

julia> using TableOps

julia> t = Table(; a = [3, 1, 2], b = ["x", "y", "z"]);

julia> pull(slice_min(t, :a), :b)
1-element Vector{String}:
 "y"

julia> pull(t |> slice_min(:a; n = 2), :b)
2-element Vector{String}:
 "y"
 "z"
